# SAIN · кейс 4 · локальная реализация онлайн-этапа

Бэкенд реализует конвейер из [ONLINE_SPEC.md](ONLINE_SPEC.md): вход `/run`,
загрузка и адаптация набора, группировка, семантическое планирование,
BM25/char/RRF, общий ответ трёх персон, проверка цитат и границ,
ограниченные repair/retry и запасные ответы. Решения описаны в
[ARCHITECTURE.md](ARCHITECTURE.md).

Выполненные проверки и открытые интеграционные вопросы:
[IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

По умолчанию **внешняя сеть выключена**. Ни деплой, ни отправка результата
организаторам в этот проект не встроены. CI с автоматическим деплоем не добавлен.
Фронтенд и интерактивный финальный чат — следующий этап, здесь реализован онлайн-бэкенд.

## Локальный запуск

Используется Python 3.11. Зависимости закреплены в `requirements.txt`.

```sh
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements-dev.txt
```

Словарь токенизатора уже лежит в `app/assets/tiktoken/` и проверяется по SHA-256.
Runtime не скачивает словари или веса. Если словарь намеренно удалён,
`python scripts/prepare_tokenizer.py` восстанавливает только публичный словарь
с OpenAI Blob; скрипт не использует токены команды и не обращается к API хакатона.

Прогон на **синтетическом**, не официальном наборе без единого внешнего вызова:

```sh
.venv/bin/python -m app.cli \
  --dataset examples/synthetic-dataset.json \
  --code synthetic-case4-demo \
  --output .local/demo-answers.json \
  --report .local/demo-report.json

.venv/bin/python scripts/evaluate.py \
  --dataset examples/synthetic-dataset.json \
  --answers .local/demo-answers.json
```

В этом режиме LLM не имитируется: семантическая стадия явно деградирует до
локального поиска, а ответы выдаёт ограниченный extractive/fallback-конвейер.
Это демонстрация работоспособности сервера и формата локального примера,
не измерение качества на задаче организаторов.

Для HTTP-сервера:

```sh
SAIN_ALLOW_NETWORK=0 \
SAIN_DATASET_PATH=examples/synthetic-dataset.json \
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Запрос в другом терминале, только на localhost:

```sh
curl --silent http://127.0.0.1:8000/health
curl --silent http://127.0.0.1:8000/run \
  -H 'Authorization: Bearer local-demo' \
  -H 'Content-Type: application/json' \
  -d '{"case":4,"dataset_code":"synthetic-case4-demo"}'
```

`local-demo` — фиктивное значение для локальной демонстрации. Оно не авторизует
никакие реальные API. `.env.example` не загружается автоматически; переменные
передаются процессу явно. `start.sh` предназначен для стенда: порт из `PORT`,
прослушивание `0.0.0.0`, без access-log. Локально его можно вызвать после активации venv.

## Тесты

```sh
.venv/bin/python -m pytest -q
.venv/bin/ruff check app main.py scripts tests
.venv/bin/ruff format --check app main.py scripts tests
```

В интеграционных тестах реальные HTTP-клиенты работают через `httpx.MockTransport`:
вызовы API и нейросети обрабатываются внутри процесса. Тестируется полный `/run`
на 99 записях, перепутанный порядок троек, общие ссылки, различие персон,
отказы на атаки, неполные/битые ответы, лимит дополнительных вызовов, таймауты,
single-flight, изоляция авторизации и отсутствие секретов в логах.

Тесты не вызывают реальную модель, метод `validate`, Google Drive, GitHub или стенд.
`scripts/evaluate.py` проверяет только локальные структуру, полноту и существование
ссылок. Он не заявляет официальную оценку или доказанную медицинскую безопасность.

## Внешний контракт пока не подтверждён

`contracts/profiles/local_example.json` и `contracts/schemas/local_*.schema.json`
— наши синтетические форматы, **не схемы организаторов**. У профиля
`verified_official=false`; он не допускается к сетевому прогону.

Чтобы завершить интеграцию после получения официальных контрактов:

1. Положить публичные схемы в `contracts/schemas/`. `$ref` нужно собрать в
   самодостаточную схему с внутренними `#`-ссылками: произвольная загрузка schema
   по сети запрещена. Проверяется разобранный `dataset`, не envelope getData.
2. Создать отдельный профиль, указать `dataset_schema`, `answers_schema` и JSON
   pointers полей. Pointers статей/экспертов/запросов относятся к `dataset`,
   pointers их полей — к соответствующему объекту. Output pointers относятся
   к результирующему envelope/ответу/ссылке соответственно.
3. Сверить входные и выходные поля с официальным примером. Адаптер сейчас
   поддерживает массив статей с вложенными разделами; другую официальную
   структуру при необходимости добавлять именно в `app/contracts.py`.
4. Только после сверки отметить профиль `verified_official=true` и закрепить
   mapping контрактными тестами. Этот флаг — подтверждение человека, не
   автоматическое доказательство правильности схемы.
5. В отдельной разрешённой проверке настроить `SAIN_CONTRACT_PROFILE`,
   убрать `SAIN_DATASET_PATH`, передать env организаторов и явно включить
   `SAIN_ALLOW_NETWORK=1`. Входной Bearer `/run` пойдёт в getData;
   `LLM_API_KEY` используется только для прокси. `HACK_TEAM_TOKEN` сервером
   не читается и токен этапа не подменяет.

Без локального набора и подтверждённого контракта `/run` возвращает безопасную
ошибку конфигурации; `/` и `/health` продолжают отвечать. В `/health` отдельно
указаны режим, наличие профиля и конфигурационная готовность к online.
Это не сертификат качества ответов или успешного official validate.

## Ресурсы и ограничения

- Один uvicorn worker, общий HTTP-клиент, до двух одновременных LLM-вызовов,
  24 начала запросов/минуту. SDK-ретраев нет.
- `/run` ограничен 42 минутами вычисления; загрузка набора — общим окном 120 секунд.
  Время ожидания очередей, backoff и повторы не продлевают абсолютный deadline.
- Общий предел 145000 токенов. Основная planning stage делит 11000 на один или
  два вызова; partial repair отдельно до 4000. Generation retry+repair —
  суммарно не более трёх дополнительных отправок.
- Каждая отправка резервирует input + max output, включая reasoning.
  Неизвестный расход после timeout остаётся зарезервированным. Overrun по
  реальному usage останавливает последующие отправки до калибровки.
- `o200k_base` — явное предположение о токенизации. Совпадение с актуальной
  моделью прокси и достаточность конвертов ещё нужно измерить реальным usage.
- Сохраняются только реальные article/section ID текущего корпуса. При слабом
  retrieval запасной отказ честно предлагает навигационный источник; это
  не гарантирует баллы по закрытому эталону.
- Regex и наличие опорной цитаты ловят часть ошибок, но не доказывают semantic
  entailment и медицинскую безопасность. Нужны реальные dev-данные и разбор атак.
- Кэш single-flight/готовых ответов ограничен по памяти, времени и области
  авторизации. Переезд/redeploy его очищает. Постоянного хранилища нет.
- Секреты из `team22_data_org/`, `.env`, локальные результаты и виртуальное
  окружение исключены в `.gitignore`. Содержимое ключей приложение не печатает.

До сдачи остаются: официальный mapping и validate, оценка смыслового поиска,
подачи и отказов реальной моделью, калибровка токенов/latency, прогон реального
корпуса в 512 МБ. Никакая из этих внешних проверок не выполнялась автоматически.
